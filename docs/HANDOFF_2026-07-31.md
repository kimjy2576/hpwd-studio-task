## 2. 이번 세션에 한 것

### 실제 제어 로직 구현 — `docs/CONTROL_LOGIC.md`

사용자가 제공한 실제 제품 로직을 그대로 구현하고 검증했다.

| 구성 | 위치 | 검증 |
|---|---|---|
| `HPWDctrl.CompStartSequencer` | `Control.mo` | 15 s→30 Hz, 20 s→35 Hz, 2분 유지, 146 s→30 Hz 복귀 |
| `HPWDctrl.EEV_Sequencer` | `Control.mo` | 450→75 pulse 조임, 5단계, 6단계 정상제어 |
| `use_real_ctrl` 스위치 | `HPWDcycle.mo` | `false` 가 기본이라 기존 동작 유지 |

숫자는 전부 파라미터다. 변경 가능하다.

### 적분 정체 해결 — t=145 → 180 → 350 → 600 완주

| 단계 | 조치 | 효과 |
|---|---|---|
| 1 | EEV 개도 순간 점프 제거 (속도제한 5 pulse/s) | t=145 → 180 |
| 2 | `T_ph` 포화선 블렌딩 (도함수 배율 무한대) | t=180 → 350 |
| 3 | **밸브 하한 75 → 30 정정** | t=350 → **600 완주** |

3 이 결정적이었다. 개도가 75 에 막혀 SH 가 계속 떨어지는데 더 닫지 못해
제어 불능이었고, 그것이 적분 정체로 보였다. **수치 문제가 아니라 제어 로직 오독**이었다.

### 물리 모델 수정

- 압축기 쉘 열결합 `AU_dis*(T_dis − T_w)` 추가
- 모터 손실 `W_elec − W_shaft` 를 쉘 열원에 추가 (기존에는 어디에도 없었다)
- 토출 엔탈피에서 `Q_shell` 차감 — **에너지 수지 폐합** (안 하면 고압이 19.5 bar 로 치솟는다)
- 어큐 분리효율에 액 재고 의존성 `f_liq = tanh(M_liq/M_liq_ref)` 추가
- 마찰 상관식을 Winandy 형태로 교체 (`W_loss0 + α·W_indicated`, L2 와 규약 통일)

### 물성 블렌딩 — `docs/PROPERTY_BLENDING.md`

포화선 도함수 점프를 8 개 함수 × 2 경계 전수 측정하고, 효과를 하나씩 쟀다.

| 함수 | 배율 | 판정 |
|---|---|---|
| `T_ph` | ∞ | **채택** — t=180 → 350 |
| `rho_ph` hL | 37.9 | 이미 적용돼 있었음 |
| `mu_ph` hV | 20.0 | **기각** — 31 % 느려지고 효과 없음 |
| `cv_ph`, `k_ph` | 5.7, 4.2 | 미측정 (우선순위 낮음) |

**배율이 크다고 대상이 아니다.** 그 물성이 계에 미치는 힘이 함께 걸린다.

## 3. 다음 세션 첫 작업 — 해석물성 + 기호 야코비안

### 상황

빌드가 실패한다.

```
error: statement requires expression of integer type
       ('modelica_real' (aka 'double') invalid)
_12jac.c:81496
  switch(jacobian->tmpVars[2640])  /* ASUB */
```

### 범인은 특정됐다

`feat/analytic-props`(7/30, 빌드 성공하는 기준점) 워크트리에 `main` 파일을
하나씩 얹어 이분 탐색했다.

```
7/30 원본 전부                              성공  ← 기준
+ Control.mo + HPWDcycle.mo + HPWDon.mo     성공  ← 시퀀서·쉘열결합·어큐 무죄
+ HPWDevap.mo                               실패  ← 범인
```

`HPWDevap.mo` 의 변경은 **증발기 습표면 블렌딩뿐**이다.

```modelica
Real w_wet[Nr,Nseg];                                    // 내가 추가
parameter Real dT_wet = 0.3;
w_wet[p,s] = 0.5*(1 + tanh((T_dp - T_w[p,s])/dT_wet));
Q[p,s] = w_wet[p,s]*(습표면식) + (1 - w_wet[p,s])*(건표면식);
```

기호 야코비안이 이 2차원 배열을 미분하며 잘못된 C 를 생성한다.
`Q` 가중합만 되돌려도 실패하므로 **배열 선언·계산 자체**가 문제다.

### 주의 — 응축기 `w_wet` 은 원래 있던 것이다

```
7/30 원본:  w_wet 7 건, dT_wet 2 건   (응축기 쪽, Real w_wet[Nr,Nsc]) — 정상
현재 main:  w_wet 17 건, dT_wet 9 건  ← 차이가 내 추가분
```

**원본 것을 지우면 안 된다.** 정규식으로 4 회 시도했으나 매번 과하거나 부족했다.
`git diff feat/analytic-props main -- modelica/HPWDevap.mo` 로 추가분을 정확히 보고
수동으로 걷어내는 편이 안전하다.

### 그리고 이 블렌딩은 효과가 없었다

적용 후에도 t=180 정체가 그대로였다(당시 실측). 기호 야코비안까지 깨뜨리므로
되돌리는 것이 맞다.

### 순서

```
1. HPWDevap.mo 의 증발기 w_wet 추가분 제거
2. 테이블+수치 기준선(600 완주, 드리프트 -0.084~+0.013 %) 유지 확인   ← 반드시
3. R290Tab.mo 를 해석물성판으로 교체 + T_ph_a 블렌딩 재적용
4. 호출부 146 건을 _a 로 전환
5. --generateDynamicJacobian=symbolic 빌드
6. 솔버 비교
```

3~4 는 이번 세션에 이미 해봤고 값 검증까지 마쳤다. `T_ph_a` 블렌딩과
`poly6` 전개(배열 루프 회피)는 **무죄로 확인**됐으니 그대로 쓰면 된다.

## 4. 미해결·미측정

| 항목 | 상태 |
|---|---|
| `-jacobianThreads=16` | **워크스테이션 미측정.** 수치 야코비안이므로 이득이 클 수 있다 (야코비안이 시간의 85 %) |

| `mu_ph` hV 부호 반전 | 물리적으로 이상하나 계에 미치는 영향은 작았다 |
| 어큐 모델 결함 2 건 | 분리효율이 액 재고와 무관(일부 해결), `xq=1` 근처 급변(`dx_sep=0.02`) |
| SH 가 600 s 에서 0 | 개도 44 pulse 인데 SH=0 — 물리 확인 필요 |
| Dymola 대비 20 배 격차 | 모델 차이(오일·어큐·습표면·충전량 구속)와 도구 차이가 섞여 있다. 추가 물리를 끄고 비교하면 분리된다 |

**사용자 지적이 맞는 경우가 많았다.** "싸이클 러너는 되는데 이것만 실패하는 게

"최소 pulse 는 30 인데 이상하다"(→ 제어 로직 오독), "실제로 동시에 바뀌는데 왜
해를 못 구하나"(→ 계단 입력이 원인).

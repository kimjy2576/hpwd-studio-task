### 1.6 섬프 온도 — 보정계수가 아니라 계산값

`dT_sump`(자유 보정계수)를 폐기하고 **압축기 쉘 벽온도**를 쓴다.

```
AU_loss*(T_w - T_amb) + AU_su*(T_w - T_su1) = W_friction
```
고압쉘이므로 오일 섬프가 쉘 안에 있어 `T_w` 가 물리적 섬프 온도.
Modelica `Comp_Chamber.T_w`, Python `compressor_chamber` 의 `T_w_K` — **같은 식**.
Python 은 계산만 하고 출력에 없었으므로 `T_shell` 로 노출시켰다.

- 남은 가정: `AU_su=3.0`, `AU_loss=5.0`, `T_amb=308.15K`.
  전부 물리량이며 쉘 표면온도·전력수지로 구속 가능.
- 잔여 보정은 `dT_offset`(기본 0)으로만.
- **문헌**: Shi 2022 (IJR 144, 163-174) — 회전압축기 sump 입구온도는 토출보다
  11~20C 낮음(주위온도 낮을수록 차이 큼). 계산된 `T_dis−T_w` 가 이 범위에 들어옴.

**함정**: Python 은 `T_amb` 를 **params 로** 넘겨야 한다(입력 BC 아님).
25C→35C 에서 `T_shell` 이 23.2→29.5C 로 크게 변한다.

### 1.8 압축기 쉘 체적 (신설 · 2026-07-26)

**충전량 인벤토리에 압축기 쉘이 통째로 빠져 있었다.**
체크리스트 414.1cc = HX 170.2 + 배관 44.0 + 어큐 200. 쉘은 0.
고압쉘이므로 쉘 가스 체적은 고압측 인벤토리의 일부이고, 오일 섬프도 그 안에 있다.

그 결과 오일 질량 싱크가 18.3cc 토출배관(냉매 0.366g)에 붙어 있었고:
```
dM_eq/dP = 33.7 g/bar,  dM1/dp = 0.035 g/bar,  tau_oil = 30s
-> tau_loop = 0.035/(33.7/30) ~ 0.031 s   (다른 시상수보다 1000배 빠름)
```
`vshell` 노드를 신설하고 오일 싱크를 거기 연결했다.

**문헌 추정** (실측 아님 — 공급사 확인 필요):
- 동일 사양: GMCC RDSK75D35WBZ3, 7.52cm3, R290, PAG 오일 190ml
- 인접 모델 치수: 15/18cm3 → φ107×254mm(2283cc, 오일 300ml),
  64.7cm3 → φ147×433.5mm(7357cc, 오일 1150ml). 오일/외형체적 13~16% 로 일관
- 7.5cm3 역산: 외형 1200~1400cc, 가스 자유공간 **300~450cc**
- ※ 행정체적 7.5cm3 과는 무관한 값 (100배 이상 차이)

### 1.9 정지조건은 충전량에서 유도할 것 (필수)

`h_rest=265.5 kJ/kg` 은 **'414.1cc 가 정확히 100g'** 이 되도록 역산된 값이다.
구성이 바뀌면 반드시 다시 잡아야 한다. 안 그러면 **조용히 과충전된다**:

| V_shell | 총체적 | 정지 회로충전 |
|---|---|---|
| 0 | 414.1cc | 99.9 g |
| 200cc | 614.1cc | 148.1 g |
| 400cc | 814.1cc | **196.4 g** |

또한 `M_dis_start` 는 회로 충전량에서 **빠지지 않고 더해진다** — 오일 ON 이면
그것만으로 +84% 과충전. 이번 세션의 오일 ON 콜드스타트는 전부 과충전이었다.

**해결**: `Cycle_L3_coldstart_charge` 사용. 초기화에 `M_total = M_charge` 를 걸고
정지 엔탈피 `h0` 를 미지수로 둔다. 오일은 `M_dis = M_eq`(정지 평형).
검증: V_shell=400cc 에서 t=0 에 M_total=0.100 정확, oil.M_dis=43.81g 자동, code=0.

구현 함정 2건:
- `h0` 를 `Real` 로 두면 t>0 에 방정식이 없어 **시뮬레이션계**가 1개 부족해진다
  (초기화 문제로 오해하기 쉬움). `parameter Real h0(fixed=false)` 로 할 것
- `PI_Controller.I` 는 자체 초기방정식이 없다. noInit 구성에선 명시 필요

**현재 병목**: 오일 ON 시 t=3~11 에서 정체.
- `oil.tau` 를 키우면 진전 (30s→t=3, 300s→t=6, 1000s→t=11).
  물리적으로도 용해/탈리는 분 단위가 맞으므로 tau=30s 는 과도하게 빨랐을 가능성
- `air_series` 는 유의한 차이 없음 (tau 고정 시 false t=4 / true t=3)
- 정체 지점 t=11 은 N 램프표의 변곡점과 일치 — 입력 기울기 불연속 의심

## 2. 폐기된 주장 (다시 하지 말 것)

| 주장 | 실제 |
|---|---|
| "다중 정상해가 있다" (3회 주장) | **없음.** 하나의 연속 단조 해족. SH=0.005 를 물리값으로 오독한 것 |
| "운전조건이 물리적으로 불가능" | 가능. 오일 모델 누락으로 순환 냉매가 5배였던 것 |
| "어큐에 액이 있으면 SH=0" | 인과 역전. 어큐는 엔탈피 중립 저장소 |
| "cp 기준 혼용이 Q 갭의 원인" | 아님. 양쪽에 같은 크기로 있어 상쇄되고 있었음 |
| "dT_sump 는 homotopy 경로 섭동일 뿐" | 아님. 물리 방정식으로 작용 |
| "T_dis 가 5K 달라서 dT_sump 가 5K 다르다" | 아님. T_dis 는 0.26K 차이 |

**SH = 0.005 는 물리값이 아니다.** `SH = 0.5*(ΔT + sqrt(ΔT² + 1e-4))` 의 ΔT=0 바닥값이며,
출구가 과열이 아닌 모든 경우에 같은 값이 나온다. **판단은 x_out 으로 할 것.**

## 4. 도구 노하우 (하드코스트로 배운 것)

1. **`-override` 는 조용히 무시된다.** `start` 속성 전용 파라미터는 `isValueChangeable=false`.
   실행 전 `verify/check_overrides.py <init.xml> "a=1,b=2"` 로 반드시 확인할 것.
   `annotation(Evaluate=false)` 를 붙여도 changeable 이 되진 않는다 → `.mo` 기본값 수정 + 재컴파일.

2. **`homotopy` 는 많이 걸수록 나쁠 수 있다.** HX 운동량식에만 걸면 3 steps 로 수렴하나
   EEV/압축기에 추가하면 수렴을 잃는다. ThermoPower 도 `fixedMassFlowSimplified`(기본 false)
   뒤에 두고 선택적으로 쓴다.

3. **`homotopy` 는 인자로 무력화할 수 없다.** `homotopy(a,a)` 도 전역 λ 경로에 참여한다.
   끄려면 연산자를 지워야 한다.

4. **모드(Integer) → 플래그(Boolean) 전환 시 암묵적 우선순위가 사라진다.**
   `initMode==3` 이 `fixedState` 를 이기던 구조를 플래그로 바꿨을 때
   `vol4(fixedState=false)` 를 명시하지 않아 회귀가 발생했다.

5. **솔버는 시나리오마다 다르다. 하나로 통일하면 안 된다.**

   | 시나리오 | 권장 | 근거 |
   |---|---|---|
   | 증발기 단품 | **gbode** | dassl 대비 25~150배 (모델 Documentation 에 기록) |
   | 사이클 정상해(ssinit) | **gbode** | 2~4초. dassl 과 값 동일 |
   | 사이클 콜드스타트 | **dassl** | gbode 는 t=0 에서 'Minimum step size 1e-20' 실패 |

   `Evap_On_Dyn` Documentation 에 gbode 권고가 이미 있었는데 세션 내내 놓쳤다.
   **레포 문서를 먼저 읽을 것.**

6. **CSV 출력은 버퍼링된다.** 타임아웃 시 부분 결과가 통째로 유실된다.
   진행 추적은 `-lv=LOG_SOLVER` 의 `call solver from X to` 로 할 것.

7. **초기화 방식에 따라 `start` 값의 의미가 정반대다.**
   `fixedState` 에서는 start 가 전부이고, 정상초기화+homotopy 에서는 무의미하다
   (homotopy 가 단순화 모델의 해에서 출발하므로).

8. **파생량이 아니라 상태량으로 판단할 것.** smooth-max·클램프가 들어간 파생량은
   물리를 가린다. 한 변수만 불연속으로 보이면 그 변수의 정의를 먼저 의심할 것.

9. **스위치를 켰다고 생각하지 말고 켜졌는지 확인할 것.** 이번 세션에서 같은 실패를
   세 번 했다: ① `-override` 가 조용히 무시됨 ② `-iif`+noInit 이 적분 안 함
   ③ `use_oil` 기본값 false 인 채로 "오일 ON" 이라 보고.
   **출력에 관련 변수가 보이는 것은 연결의 증거가 아니다.**
   판정 전에 항상 **섭동에 반응하는지** 확인할 것(값을 크게 바꿔 결과가 변하는가).

10. **좀비 프로세스 확인.** nproc=1 이라 이전 실행이 살아있으면 시간 측정이 오염된다.
